## 1. 一句话产品定义

做一个色彩鲜明、可在 Mac 与 iPad 浏览器中玩的儿童乐园冒险游戏：白天免费游玩水上乐园、观察动物并结交小狗；晚上带上免费手电筒，利用飞行、隐形和小狗嗅探找到三条线索，点亮乐园的星星灯。

首版追求“孩子的点子真的能玩”，不是展示几张场景图、几个按钮或一份需求看板。目标体验为约 10–15 分钟一轮，完成后可以继续自由游园；该时长是设计目标，须通过试玩修正。

## 3. 本轮范围：先做独立完整游戏

### 必须交付（P0）

1. 一个连通的乐园地图：入口广场、水上乐园、动物园、小狗活动区。
2. 实际可玩的白天活动，以及可主动进入的夜晚寻线索任务。
3. 三个可切换的可爱角色外观；所有角色都能飞行、隐形，并拥有免费手电筒。
4. 会跟随、可互动、能协助寻线索的小狗。
5. 桌面键盘与触屏双操作；英文／中文界面切换；暂停、继续、重新开始、本地存档。
6. 完整胜利结局、继续游园、确定性测试和真实浏览器截图证据。

### 明确不做

- 不做三台 iPad 实时联机、账号、云存档、排行榜或联网对战。首版是三人共同设计、各设备独立试玩；同一设备可轮流操作。三角色切换不等于三人联机。
- 不做实时语音识别、TTS、LLM 对话、AI 自动改代码或教师控制台；这些属于课堂编排层，不是本游戏启动依赖。
- 不做战斗、血条、捕捉升级、Boss、宠物饥饿倒计时、失去宠物、付费门票或强制刷金币。
- 不沿用 Naomi 的回合制／双 iPad 联机架构，也不套用 Martin 的怪兽战斗系统。
- 不要求外部模型、付费 API、ComfyUI、远端 MSI 或外网 CDN 才能运行。
- 不做无穷地图、复杂建造或额外游戏模式；先把本规格闭环做好。

## 4. 玩家体验与地图

### 4.1 视觉与镜头

采用俯视偏等距的 2.5D 绘本风格，表现圆润人物、彩色水滑梯、清楚的动物轮廓及柔和灯光。默认不是越肩第三人称，也不引入完整 3D 物理与骨骼绑定。

镜头跟随当前角色，接近地图边界时停止；重要设施都有可读图标。角色不能被高大装饰完全遮住。三个角色使用不同配色和轮廓，默认标为“角色 1／2／3”，不把学生名字当作账号或能力职业。

### 4.2 必须可见、可互动的内容

| 区域 | 最低内容与实际反馈 |
|---|---|
| 入口广场 | 免费入园标识、简明地图、游园护照、星星灯控制台、夜游入口。 |
| 水上乐园 | 彩虹滑梯、浅水戏水区、喷水设施、免费食物摊；完成一次滑梯体验可得印章。滑梯必须有实际移动动画和落水反馈。 |
| 动物园 | 至少 6 种清楚可辨的动物，例如狮子、鳄鱼、长颈鹿、大象、企鹅、猫头鹰；至少 3 种有不同互动反馈。动物为本轮选型，不标作全部来自孩子原话。 |
| 小狗活动区 | 一只会呼吸／摇尾巴／跟随的小狗；抚摸、领取免费狗零食、喂食。人的食物与狗零食明确区分。 |
| 游客与环境 | 默认约 12 名游客分布于乐园，使用简单循环路径；性能降级时可减至 6 名。游客不堵路、不充当联网真人。 |

四区在同一世界中连通；不靠四个互不相关的页面冒充世界。围栏、树木、水边与路径有明确通行规则。浅水区可玩，深水或地图外不可误入。

## 5. 核心闭环与任务规则

### 5.1 白天：收集三枚游园印章

开始新游戏 → 选择角色 → 免费入园 → 自由探索三个活动 → 集齐印章 → 玩家主动选择夜游。

| 印章 ID | 唯一完成条件 |
|---|---|
| `waterpark` | 按互动键实际乘坐一次彩虹滑梯并回到安全出口。直接飞到出口不算完成。 |
| `zoo` | 在近距离互动点观察 3 种不同动物。重复点击同一种不增加计数。 |
| `puppy` | 对小狗完成至少一次抚摸和一次喂狗零食；两项顺序不限。 |

食物、狗零食、滑梯、动物观察和所有区域均免费。人的食物提供简短开心反馈，不建立经济系统。没有体力付费、道具消耗或购买门票的隐藏门槛。

三枚印章按世界存档共享，不按角色重复刷。集齐后出现“准备好夜间探险了吗？”；可以继续白天游玩，不能突然强制变黑。白天没有时间失败。

### 5.2 夜晚：用三种能力找到三条线索

夜游首次开启给出可跳过的短说明：乐园的星星灯还没亮，找到三枚星星线索即可恢复。每个角色自动获得无限电量的免费手电筒；基础路灯和动物园灯始终提供可辨认的安全路径。

三条线索在进入夜游时激活，可以任意顺序完成。关卡位置固定，不用随机生成造成不可达；每条线索只收集一次。

| 线索 ID | 可验证的玩法条件 |
|---|---|
| `sky` | 水上乐园有一个清楚标出的低障碍与高处观察点。处于飞行状态到达该点，用手电照亮至少 1 秒，再按互动键取得星星线索。 |
| `quiet` | 动物园公共步道旁的害羞猫头鹰观察点。处于隐形状态并停留在标记范围，用手电照亮至少 1 秒，再互动取得线索。禁止穿入动物围栏内部。 |
| `trail` | 在小狗起始嗅探点按互动键，小狗沿固定安全路径展示 3 个脚印提示；玩家可随时重新呼唤。到终点用手电照亮至少 1 秒，再互动取得线索。 |

“照亮”必须通过光照范围、连续照射时间和正确区域条件判断，不能仅点击远处图标领奖。射程统一为配置项 `torchRange = 140` 世界单位；范围内目标仍须满足对应任务前提。交互距离统一为 `interactionRadius = 48` 世界单位。角色普通移速默认 `120` 世界单位／秒。

首版手电采用随角色移动的圆形光晕，而不是额外瞄准杆，以减少触屏操作。小狗终点满足嗅探路线已完成后才可领取；狗跑到终点不自动把奖励加给玩家。

收齐 3 条线索 → 返回广场控制台互动 → 点亮星星灯 → 播放柔和庆祝动画 → 胜利页展示 3 枚印章与 3 条线索 → 继续白天游园或重新开始。收齐线索本身不跳过最终互动。

### 5.3 温和紧张感与退出夜游

夜晚的 scary 用树影、轻微环境变化、发光脚印和悬念提示表达；不使用突然贴脸、血腥、抓走小狗、惩罚性死亡或尖叫音效。

暂停菜单始终提供“回到白天”。切回白天保留印章、已完成的嗅探与已取得的夜间线索；再次夜游可继续。完成结局后进入 `completed` 自由游园状态，不能通过反复点灯重复奖励。

## 6. 操作、能力与小狗

### 6.1 基础操作

- 桌面：WASD／方向键移动；E 互动；F 飞行；I 隐形；L 开关手电；1／2／3 切换外观；Esc 暂停。
- 触屏：左侧虚拟摇杆，右侧互动、飞行、隐形与手电按钮；上方角色切换和暂停。菜单按钮触控区域至少 44×44 CSS 像素，常用动作按钮优先 52×52。
- 地图交互点接近后显示图标与短提示；点击远方设施不触发互动。小狗嗅探复用互动键，不增加第四种复杂操作。
- 双指同时移动＋按能力必须有效。只有游戏输入区域阻止默认页面拖动，不破坏菜单、页面缩放与其他区域操作。

### 6.2 飞行与隐形默认参数

| 能力 | 行为与边界 |
|---|---|
| 飞行 | 持续 5 秒、结束后冷却 3 秒、速度为普通移动的 1.25 倍。可越过标记为 `low` 的障碍，不可穿越外边界、建筑或 `high` 动物围栏。可再次按键提前结束。 |
| 安全降落 | 飞行结束在当前位置寻找合法地面；若没有，回退到起飞时记录的合法位置。绝不落入深水、墙里或动物围栏。 |
| 隐形 | 持续 8 秒、结束后冷却 4 秒。玩家仍能看到半透明自身；不改变物理碰撞。害羞猫头鹰不再躲开，小狗始终能跟随主人。 |
| 手电 | 夜游默认打开，不消耗电量；切换外观不丢失。白天按钮可置灰并显示“夜游时可用”，不产生误导性的暗画面。 |

飞行任务的观察点必须能从最近安全起飞点在约 2 秒内到达，留出照射与互动时间；不能靠增加默认能力时长掩盖地图不可达。

飞行与隐形互斥：发动另一个能力先结束当前能力，并执行安全降落及原能力冷却；尝试发动仍在冷却的能力只显示提示，不取消当前有效能力。冷却按游戏有效时间计时，切换外观不能刷新冷却、持续时间或任务条件。

### 6.3 小狗行为

小狗只使用简单的 `idle / follow / sniff / celebrate` 状态；用地面可通行路径跟随，不能直线穿墙。主人飞行时小狗在地面跟随或原地等待；主人离开过远且存在安全位置时可柔和回到主人附近，不能成为卡关条件。

嗅探期间切换角色不重置路线。暂停、模态说明和后台挂起时，小狗任务移动一起暂停；中断、刷新后恢复为跟随状态，可重新呼唤开始未完成的路线。已经完成的 `trailRevealed` 标记保留。

## 7. 状态机与不可破坏规则

用业务阶段 `DAY / NIGHT / COMPLETED` 与界面状态 `TITLE / SELECT / PLAY / DIALOG / PAUSED / VICTORY` 分开建模，不写成散落的布尔变量互相猜测。

1. 只有 `uiState = PLAY` 且页面可见时，才允许玩家移动、任务交互、能力计时和小狗任务推进。标题、选角、对话、暂停和胜利页必须冻结这些行为。
2. 白天集齐全部印章后才可从正式流程进入夜游；测试入口单独隔离，不混进普通 UI。
3. 印章和线索均为集合，不是无限累加计数；重复事件具有幂等性。
4. 切换角色只换外观，位置、地图阶段、背包、任务、能力剩余时间及冷却不变。
5. 所有任务都能由任意一个角色完成。不得要求三个角色同时站位，或让缺席学生导致无法通关。
6. `pointerup / pointercancel / lostpointercapture / blur / visibilitychange`、切换界面和旋转屏幕都清空按键／触点状态，防止粘键和后台移动。
7. 返回页面时重置上一帧时间，单帧模拟步长设上限；后台停留不能变成瞬移或瞬间结束能力。
8. 模态对话只能响应对话 UI，不允许穿透点击到游戏世界。同一互动按住不反复领奖。
9. `winTriggered` 必须单次生效。重新开始需明确确认，只重置本游戏存档，不能清空浏览器全部存储。

## 8. 存档、语言与隐私

单设备保存使用 `localStorage`，键名为 `adventure-world:save:v1`。存档最少字段：

```json
{
  "schemaVersion": 1,
  "gameId": "adventure-world",
  "worldVersion": "1",
  "phase": "DAY",
  "avatarId": "avatar-1",
  "position": {"x": 0, "y": 0},
  "stamps": [],
  "animalsObserved": [],
  "puppyPetted": false,
  "puppyFed": false,
  "trailRevealed": false,
  "clues": [],
  "winTriggered": false,
  "locale": "en",
  "muted": true
}
```

示例的 `(0,0)` 是格式占位，不是指定出生坐标；真实出生点由地图配置给出。载入必须校验类型、枚举、可通行坐标和阶段前提，非法位置回安全出生点。飞行／隐形不以进行中状态恢复，重新载入安全落地并把两种能力冷却重置为完整冷却值，防止刷新绕过冷却。

任务完成、阶段切换、设置变化后保存；位置保存做节流，不逐帧写磁盘。存档损坏或版本不兼容时说明情况并提供新游戏，不让页面白屏。存储被禁用或写入失败时仍可完整游玩，但持续显示“本次进度未保存”，不能显示保存成功。

切换语言、静音或角色不得覆盖任务进度。默认英文，提供中文切换；操作说明、任务、按钮、动物信息和结局都要覆盖，不能只翻译首页。默认静音；启用声音须由用户交互触发，首版没有音乐也不能阻塞交付。

无登录、遥测、聊天记录、录音或个人信息上报。学生名字仅在这份私有规格中记录；公开页面的署名与 GitHub 发布等待 Dean 另行授权。

## 9. 实施约束与落盘规划

## 10. 质量、性能与验收

### 10.1 性能目标

Mac 与测试用 iPad 横屏均能完整游玩；竖屏仍能看见菜单，必要时提示转横屏。画布处理设备像素比并设置渲染上限；触屏按钮不被安全区域遮住。

目标：核心首屏资产总计不超过 8 MB；目标设备游玩时稳定达到约 30 FPS 以上，Mac 优先达到 50–60 FPS。以上是待测指标，不是既成性能承诺。低帧率先减少游客、粒子和阴影，不删必需的动物种类、交互点或任务。

### 10.2 必测项目

| ID | 操作与通过条件 |
|---|---|
| A01 | 全新存档启动，标题和选角页持续按移动键，角色及任务均不推进。 |
| A02 | 任一单独角色从新游戏走完白天→夜游→点亮星星灯→胜利→继续游园，不依赖测试捷径。 |
| A03 | 三种动物观察去重，滑梯只有实际乘坐才算，小狗抚摸与喂食均必需。 |
| A04 | 同一印章／线索连点与长按只领取一次；未集齐线索时控制台不能胜利。 |
| A05 | 飞行可过低障碍、不可穿高围栏；在不可站立区域到时或切换能力都能安全降落。 |
| A06 | 非隐形不能拿 `quiet`；隐形不取消普通碰撞；能力冷却不可用换角色刷新。 |
| A07 | 未开灯或照射不足 1 秒不能拿线索；照射中断后连续计时归零。 |
| A08 | 小狗路线能启动、完成和重启；跟随不穿墙，主人飞行不导致小狗或任务失效。 |
| A09 | 三线索的 6 种收集顺序均能通关；重复阶段切换不造成软锁。 |
| A10 | 回白天→再夜游保留已得线索；结局动画只触发一次。 |
| A11 | 暂停、对话、标签页后台与恢复不移动角色、不跳时；菜单点击不穿透。 |
| A12 | 双指移动＋能力、移出按钮再松开、`pointercancel` 和失焦后没有粘键。 |
| A13 | 在白天、夜晚、完成后分别刷新，恢复合法进度；损坏／不兼容／禁止存储均不白屏。 |
| A14 | 中文／英文、角色外观和静音切换保留进度；重新开始只清本游戏存档。 |
| A15 | 本地服务下断开外网仍可完成一局；没有缺失资产、未捕获异常或失败的必要资源请求。 |
| A16 | 视口 1024×768、1180×820 与桌面测试中，HUD、说明、胜利页及常用按钮无遮挡；记录实测帧率与加载量。 |
| A17 | 实体 iPad Safari 验证多指触控、旋转／返回及本地存档；只有模拟环境时必须写 `NOT_TESTED_ON_PHYSICAL_IPAD`，不能标作实体通过。 |

状态、碰撞、任务前提、计数幂等、存档校验和六种线索顺序需自动化测试。真实浏览器流程必须从正式新游戏入口完成 A02，并记录过程；测试钩子只能用于补充边界复现，不能代替整局试玩。

### 10.3 必须回收的证据

截图至少包含：白天总览、水滑梯实际游玩、动物园互动、小狗嗅探、夜晚寻线索、最终胜利，共 6 张。全部由运行中的游戏截取，不用概念图或生图代替。

`results.json` 每项记录 `test_id / status / environment / evidence / notes`，失败项记录复现步骤。`ACCEPTANCE_REVIEW.md` 写明实际根路径、版本／提交或关键文件哈希、启动地址、测试设备、通过与未通过项、未测项目。

验收口径：先报告 `DESKTOP_PASS` 与 `TOUCH_EMULATION_PASS`；只有 A17 真实通过后才能报告 `PHYSICAL_IPAD_PASS`。任何 P0 卡关、错误存档、模态下继续运动或无限领奖均为 `CHANGES_REQUESTED`，不能用“画面好看”抵消。未做实体测试可以交老师试玩，但不能宣称全面验收完成。

## 11. 执行顺序与交接

获得开发授权后，执行者按以下四步直接推进，不另写一套替代 Spec：

1. 建立隔离项目，先跑通角色移动、输入清理、状态机、存档及地图碰撞。

4. 跑自动化与正式入口整局测试、修复失败项，交回启动方式、截图和验收报告。

不为普通文件命名、布局细节或配置值反复询问。仅在发现旧项目需要覆盖、授权范围外写入、付费资源或公开发布时停下对应动作；其他独立工作可继续。不要启动蜂群、自动追加第二款游戏或扩大为完整课堂平台。
