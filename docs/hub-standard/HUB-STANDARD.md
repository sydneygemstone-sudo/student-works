## 0. 先校验唯一入口，再做作品

仓库根目录的 `HUB-ENTRY.json` 是定位入口，`docs/hub-standard/LOCK.json` 记录版本、文档和基准文件 SHA-256；本文件是唯一规范正文。资料库同名文件是逐字节同步镜像，不是另一份可独立改写的标准。

执行顺序：
1. 读取 `HUB-ENTRY.json` → `docs/hub-standard/LOCK.json` → 本文件。
2. 确认 `standard_id=CLASSROOM-HUB-R5-20260923`、`version=3.0.0`、`status=APPROVED_LOCKED`。
3. 在仓库根运行 `python3 scripts/verify_hub_standard.py`。版本、指纹或锁定基准不符就停止模板套用，报明冲突，不搜索一个“差不多”的旧版继续。
4. 读取本课真实 brief、所有相关开发日志、教师反馈、候选目录、Git 提交和发布回执；再生成本课数据。
5. 先在该课程自己的目录/候选工作区制作。锁定样板保持不动，不把新学生数据写进两份黄金样板。

正式参照：固定提交中的 `classroom-2026-09-22/kehan-hub.html` 与 `harrison-zavier-hub.html`，连同各自 comparison、development、costs、guide、parents、review 页面及共享 CSS/JS。不要只截一张图模仿外观而遗漏表达内容。

仓库 `AGENTS.md`、`CLAUDE.md` 和 `docs/hub-standard/SKILL.md` 都只指向这里。没有把文档自动安装到所有产品，也没有修改不可访问的 Project 系统指令；新对话/新执行环境必须实际读取入口。自动校验是防漂移检测，不是管理员级别禁止写入。

## 1. 锁定的首页信息顺序

首页第一屏必须回答：**花了多少，走到哪一步，人工做要多少投入，哪一阶段的效率可比较；然后我该玩什么、该看哪项结论。**

1. **四张顶部指标卡**：预算已用/总池＋bar；总体阶段进度＋bar；人工成本/工时估算；时间与工具成本效率倍数。
2. **主题真实大图**：作品、学生、核心目标、可点击试玩和完整开发过程入口。
3. **本课结论**：一至两句，写清是双版比较与融合，还是已经完成的保留/弃用决策。
4. **版本卡并列**：真实截图、分支/工具/版本号、长处、短板、状态、Token、成本、暂评、试玩与报告入口。
5. **总体阶段状态图**：起点、已完成阶段、当前阶段、待完成关口及下一步；与顶部百分比同源。
6. **开发分支路线图**：共同 brief → 并行实现 → 每条分支的实际结果 → 保留/终止/融合提案。实线表示已有结果，虚线表示未实施；弃用线必须终止，不能误画为参与融合。
7. **六张内容入口卡**：版本测评、完整开发、投入/人工/效率、家庭 iPad 指南、家长展示、试玩反馈/Bug。
8. **最新版下载**：清楚区分 iPad 在线单机和电脑离线 ZIP。

固定 r5 的层级、卡片密度、数字优先、可展开细节和可读性。可按游戏主题改色彩、美术背景与少量字体，不得改回只堆本轮改动的长日志。说明和计算口径放可展开区/专页，不霸占指标卡；小字不能承担唯一的重要限定。

## 2. 数据会变化，模板不退化

### 2.1 预算使用

首页直接显示 `A$已记录投入 / 总预算`、百分比及 bar。不要显示 `1×50`、`2×50`，也不要把批准预算、已用、余额拆成三张卡占掉人工/进度的位置。

默认审批仍是每位学生 A$50，特殊批准优先；这是计算规则而非首页口号。`使用率=已记录投入/批准预算×100%`。未知是 null/未计量，不是零；费用超预算时数值显示实际比例，bar 可在 100% 截止并明确超额，不隐藏。

读实际 Codex/Claude 会话用量：累计值取正确终值或增量，流式行按稳定请求标识去重；输入、缓存读取、不同 TTL 缓存写、输出分别计价；推理在输出内的不再重复加。包含试错、弃用和修 Bug 消耗；其他课程不混入。会话仍打开不等于全部空闲时间都是开发时间。

历史账本保留当日价格/汇率及来源；新账本核对其适用价格，不能把旧快照当现价。API 等值与订阅额外扣款、发票实付、教师人工分别呈现。没有主控回执时明确缺口。所有卡片/账本引用同一数据源。

### 2.2 阶段进度

默认阶段：构想 → Brief → 原型 → 版本评估 → 家庭适配 → 验证与呈现 → 实机与定稿。

每个阶段有状态、依据和下一步。默认采用等权完成阶段/适用阶段，顶部百分比、bar 与图一致。批准样板当时是 6/7≈86%，**86% 只是样板当时的数据，不能照抄成以后所有项目的完成率。** 阶段数/权重调整要说明，不为美观把未测标为完成。

HUB 获批与实体 iPad 试玩是不同验收项；本次批准模板不自动让实体测试通过。尚未决定开发的融合版、跨家庭联机不计入已完成阶段，作为后续范围单列。

### 2.3 人工成本估算

对“当前交付一次重建”做任务拆解：需求、场景/角色、玩法规则、输入/触屏、服务器或单机适配、双语 HUB、测试打包。为每项给工时区间，汇总区间和中点，再乘清楚标记的估算时薪。当前交付的工作范围不能重复累加所有旧版。

r5 使用的 A$63.44/h 是沿用 Alex/Victory 的历史估算参数，不是新市场调查或实际报价；以后可以按已批准参数调整，但必须标记来源、日期或“假设”。工时是规划估算，不是已投入人工，也不是商品售价。禁止只给一个漂亮总额而无工作项依据。

### 2.4 时间/成本效率

必须有直观倍数，同时能展开公式与范围：
- `时间倍数=同阶段人工估算工时/同阶段已记录开发时间`。
- `工具成本对照倍数=同阶段人工估算费用/同阶段已记录工具 API 等值费用`。

并行会话使用联合时间窗口或明确的区间并集，不把两个并行时长直接加起来当等待时间。停止/空闲段如何处理必须说明；有明显中断时分别记录。初版开发不能拿来和完整 HUB＋全部后续调试的人工工作量作全项目对比。

**首页必须标明所比阶段。** r5 将当前整套交付人工估算与“课堂原型阶段”倍数分开；未知主控/教师工时与费用没有被视为零。完整成本缺失时不报“全项目节省×倍”。估算中点不是统计中位数；零/未知分母不得产生 Infinity 或 NaN。没有足够证据就显示“待核验”，保留卡片，不编造数值。

## 3. 两种版本结论，绝不能套错

### A. compare_and_merge：Kehan 型

保留 Claude 飞船探索、Astra 冰火战斗两条各自最新版。对比维度至少包括飞行探索、地面手感、冰冻射击、失败重试、家庭 iPad。

每项写清：Claude 优点/不足、Astra 优点/不足、融合时取什么、怎样验证。融合方向可以是 Claude 的阶段/主动飞行＋Astra 的地面反馈，通过统一动作接口先做一个小切片；它是提案，没实现就不能称已经融合。

不能使用“不是谁都要留下”等泛泛淘汰口号，也不能以“只保留最新版”为理由删除有互补价值的另一个分支。首页两张卡均有可玩入口，每个保留分支只开放一个当前版本。

### B. retain_and_reject：Harrison / Zavier 型

教师已确定：Opus 两次修复后仍有影响课堂使用的 Bug，因此停止投入，保留 Astra。路线图上 Opus 终止，Astra 才继续单机化/手感/平衡；不是还等两版竞争，也不是自动进入融合。

保存局部测试、失败反馈和取舍的区别：有脚本截图不等于三台 iPad 在课堂可用；不可写成“从未测试”。原日志可核验入口、移动、名字输入的问题；两次修复仍失败的最终结论归因教师反馈，不虚构技术因果或具体时刻。

弃用卡保留截图、失败原因、成本、记录链接，不给试玩入口，也不打进可玩 ZIP。无法使用不能靠美术分平均成推荐。其他课程先根据自己的结论选这两类之一，或标 decision_pending，不能机械套本课人名和故事。

## 4. 开发日志必须呈现完整形成过程

主线必须从最初可核验构想/brief，经过工具实现、原型、试玩、修复、取舍，一直到当前交付和下一步；**不是最新一轮修补的 changelog**。版本增量可折叠做附录，不能代替项目历史。

先给分支状态图，再给按真实发生先后排列的时间线。每个重要节点包括：
1. 对话/brief 重点：当时需要什么、舍弃什么约束。
2. 工具大致方向：例如环境检查 → 模块并行/写代码 → 本地预览 → 截图/规则测试 → 交付，不能只有“AI 开发”。
3. 技术栈与选择理由：例如 Three.js 渲染、JS 状态机、独立规则引擎、Node.js/WebSocket 课堂服务、浏览器本地传输、Pointer Events 触控。按实际记录写，不用模板凭空补。
4. 结果与影响：这一节点让作品变成什么、后续选择如何变化。
5. 时间/状态/依据：课堂 brief、工具日志、教师反馈、发布回执；缺时间就只标阶段，不编精确分钟。

家长先读得懂结果，需要时展开技术信息。只公开脱敏摘要，原始对话/录音/内部推理/密钥不公开；brief 中举例的假想台词不冒充学生原话。学生提出需求和做决策、教师组织验收、AI 参与实现分别表达。

## 5. 测评与反馈

版本卡显示长处和短板，不能只给一个星级。沿用作品暂评维度：美术主题40%、手感30%、玩法闭环20%、清晰度10%，或说明经批准的其他口径。有观察才评分，换 HUB 版号不自动涨分。

分开标记：规则测试、浏览器 UI、WebKit/触屏模拟、实体 iPad、儿童实际试玩、注入场景/固定策略模拟。不要把脚本通关称成人类通关或胜率预测；不要把未测写 PASS。评分是作品观察，不是学生成绩或模型综合排名。

反馈支持本机保存/导出/明确的提交入口。保存到浏览器不等于已发老师；GitHub Issue 只打开待用户发送的表单时要说清。公共反馈不得带学生录音和敏感信息。

## 6. 游戏端默认：单机、双语、左侧栏、防缩放

英语＋简体中文；只有 Alex 按既定明确要求保留繁体，例外不外扩。动态战斗文案、开始/失败/胜利和语言切换都检查。大字标签如 MOVE / CHOOSE / SURVIVE、移动 / 选择 / 生存不加装饰性句号；普通说明保留正常标点。

每条保留分支都必须有家庭 iPad 单机可玩入口。不需要老师电脑开机、键盘、房间或队友到齐。采用两名 Bot 的单机版不代表三台 iPad 联机通过。初次加载要网络、不存档等边界据实写。

**所有保留游戏配左侧竖向工具栏**：当前 HUB、语言、暂停/继续、可选全屏。给摇杆独立空间，不能回到底部遮说明/按键。最小44×44 CSS px，r5样板用48px；检查1024×768、768×1024及矮横屏，不能只测桌面。

**双击/快速连点导致浏览器放大是阻断发布的常见 Bug，必须进入每次执行提示词。** 首次交互前配置手势；画布、摇杆、持续操作按钮接管游戏手势；普通菜单保留正常点击，HUB 阅读页保留滚动和放大。必要时在限定游戏区域增加非被动触摸防护；仅改 viewport、仅拦 pointerdown 或仅写 dblclick 都不能当作完整修复。

验证画布/按钮/摇杆连点前后页面 scale、宽高、坐标；保留双指移动＋攻击/冰冻；pointercancel/lostpointercapture/失焦释放输入。开始、名字输入、重试、语言和暂停不能失效或双触发。暂停实际模拟及计时，恢复不跳时；角色与镜头一致平滑。

共享 `device-kit.js`、`device-kit.css`、`touch-guard.js` 按 LOCK 的样板校验后复用。HTML、内部模块、动态注入 CSS、语言脚本与下载包一起做版本缓存校验，不能只给首页加 ?v。

## 7. 发布、隐私与范围

电脑离线 ZIP 在新目录真实解压启动并屏蔽外部资源，运行文件逐项比对在线验收版；包含运行时依赖说明，不要求 iPad 装 Node.js。离线返回 HUB 也应有效。不支持 file:// 的不得宣传双击 HTML 就能玩。

学生音频克隆只用本地模型；原声、参考音频、克隆资产、生成语音均不进公开仓库/Pages/ZIP。需要 Git 管理只能用已核对权限的私密仓库。公共内容只用必要名、作品截图、脱敏摘要与汇总账目；不含完整会话、内部路径、家庭网络地址、凭据或联系方式。

发布前检查当前远端与工作区，避免覆盖并行更新，只提交批准范围。不 force push，不因发布就删原始课堂源，不动无关学生。Git 提交、部署成功、线上读回和实机验收分别声明；下载和线上关键文件做 SHA-256。后台进程活着不等于交付完成。

## 10. 防漂移、升级和历史管理

版本锁包含黄金样板源文件、正式文档和执行入口的指纹。校验缺文件、旧ID、哈希不符即失败；不生成自动更新锁的参数。运行 `python3 scripts/verify_hub_standard.py --self-test` 应证明旧入口/缺文件/被修改文件会被拒绝。

黄金样板提交同时用 `hub-approved-r5-20260923` 标签保留。普通内容/游戏迭代到新课程或候选版本，保留正式标准不动；正式改变布局、指标定义或版本判断规则，先做候选由 Dean 明确批准，再升版本、更新入口/指纹、同步资料库、记录新批准。不能擅改标签指向、用“最新”替代审批。

GitHub 的 hub-standard-lock 检查若启用，会对相关改动运行 preflight 和负向测试；这不自动等同于 GitHub 分支保护或阻止所有部署，管理员仍有修改权限。根入口及执行提示词要求在制作前主动通过检查。

v1.0、v2.0 不再保留为当前目录的并行规范。资料库在原文件路径原位升级；Git 历史自然保留。Alex/Victory 原作仅保留为设计演进参考，其不含 r5 指标/全程路线的旧结构不能作为新任务默认来源。
