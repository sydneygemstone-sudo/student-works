01
Michael · Game Product Design Lab

“难一点”
不是一个设计。

今天不教你“怎么把数值调狠”。我们要学的是：怎样把玩家的体感，变成一个可以实现、可以取舍、可以测试的产品方案。

感觉“太简单”
→
定位哪里简单？
→
方案改哪个机制？
→
证据怎样算改好？
教师提示：先让学生说，不替他补答案。今天评价的是“设计信息是否完整”，不是话说得长不长。
02
Home Test → Design Brief

“我觉得太简单，做难一点。”
这句话少了什么？

位置

是第几块平台？追逐？收集？出口？还是整局节奏？

原因

为什么简单？反应时间多、跳距短、没有路线选择，还是追兵没有压力？

目标行为

你希望玩家因此开始观察、判断、练习时机，还是承担风险？

方案

速度、平台、规则、路线、奖励，到底改哪一个？

取舍

变难后会不会让触屏更难控制、让镜头来不及读、让收集变成重复劳动？

验证

跑几次？看成功率、失败原因、动作变化，还是主观乐趣？

体感是入口，不是施工图。

03
A/B Experiment

我完全照字面做了一个“更难”版。

我没有问“难在哪”。所以我同时改了：时限、水晶数、追兵、重力、跳跃力度、Coyote time、Jump buffer……

标准版 1.1

8/12 水晶 · 300 秒 · 8.8 速度 · 0.16s 边缘宽限 · 0.20s 跳跃缓冲 · 追兵上限 8.5

打开标准版

vague-hard 1.2

10/12 水晶 · 180 秒 · 8.35 速度 · 0.08s 边缘宽限 · 0.10s 跳跃缓冲 · 追兵上限 9.35

打开字面“难一点”版

问题：新版如果不好玩，你能指出究竟是哪一个变化导致的吗？如果不能，这就是模糊需求的成本。
04
Difficulty ≠ One Number

难度至少有 9 个旋钮。

时间压力倒计时、障碍速度、预告时间风险：没时间理解
操作精度平台宽度、跳距、落点窗口风险：触屏挫败
追逐压力敌人速度、距离、恢复速度风险：没有观察空间
路线判断分叉、捷径、安全路/危险路风险：提示不清会变成猜
动作组合跳+转向、连续跳、冲刺+落点风险：一次教太多
信息压力可见范围、预告、记忆风险：不公平
资源取舍水晶、护盾、救命机会风险：价值不清
风险/奖励危险路线提供额外收益风险：奖励不值得
失败成本检查点、重来距离、失去资源风险：浪费练习时间
05
Case 1 · Temple Run
TR

Temple Run：动作很少，组合很深

官方介绍的基础动作就是转向、跳跃、滑行；再叠加金币、强化与持续跑远的目标。[1]

动作词汇少

玩家不用先记十几个按钮。

时机越来越紧

同样的动作，在不同障碍顺序中形成反应与预判。

奖励改变路线

金币与强化可以诱导玩家承担额外风险。

学到什么：不要先问“能不能再快 20%”。先问“我能不能用已有动作制造一个新的判断？”
06
Case 2 · Subway Surfers
SS

简单控制，不代表简单游戏

App Store 的编辑介绍把核心概括为：简单滑动控制下的 jump / slide / dodge，并特别强调换道与跳跃不应该靠猜，而要有紧密、响应明确的控制。[2]

看见火车 / 障碍
→
识别跳？滑？换道？
→
执行在正确时间输入
→
反馈马上知道成败原因
产品原则：可读性越高，你越有资格提高速度。看不懂的“快”不是技巧挑战，只是猜。
07
Case 3 · Roblox Obby
RBX

平台本身就是难度设计语言

Roblox 官方 Classic Obby 教程明确采用从容易到更难的课程，并加入移动、推动、伤害等平台变化；它还提醒平台跳距如果一开始过难，玩家可能直接退出。[3][4]

宽平台
变窄
更远 + 旋转
测试

位置、尺寸、朝向、运动方式，都可以改变同一个“跳跃”动作需要的判断。Roblox Platformer 模板还展示双跳、冲刺、翻滚、长跳、移动平台与金币等扩展机制。[5]

08
Input Is Not Gameplay

“键盘跳跃”只是输入。
游戏设计的是动作。

Roblox 的输入文档把“jump / sprint / shoot”作为动作，再为不同硬件绑定输入。[6]

设备思维

“把空格键变难一点。”

这没有说明玩家要掌握什么。

动作思维

“让玩家在连续两次跳跃之间，必须判断落点方向。”

键盘、触屏、手柄都可以实现同一个动作目标。

Crystal Escape 的原则：iPad 和键盘可以有不同输入方式，但应该尽量考同一种游戏技能。
09
Case 4 · Vector
V

跑酷高级感来自“时机谜题”

Vector 的官方 Steam 描述列出 run / vault / slide / climb，并把复杂关卡描述为快速的 timing puzzles。[7]

动作

跑、翻越、滑行、攀爬。

时机

什么时候使用哪一个动作，决定流畅度。

关卡

关卡排列负责提出问题，而不是只提高人物速度。

迁移：如果 Crystal Escape 将来加入冲刺或翻越，先用安全区教会，再用组合区测试，最后再加入变化。
10
Hard but Boring

六种“确实更难，但可能更无聊”的改法

全部加速

反应时间变短，但没有新决定。

平台全部缩小

同一个动作只是容错更低。

追兵贴脸

玩家失去观察与探索空间。

失败重跑很远

练习目标被重复劳动淹没。

随机且没预告

失败后不知道自己能学什么。

目标数量堆高

收集更多，但路线和策略不变。

11
Hard and Interesting

更好的难度：制造新问题，并让失败可学习。

Teach → Test → Twist

教：安全环境第一次出现机制。
测：单独要求玩家掌握。
变：再和已有机制组合。

Risk → Reward

安全路更慢但稳；危险路更快或奖励更多。玩家主动选择难度，而不是被系统硬压。

Read → Decide → Act

先看清问题，再做选择，再执行。速度可以压缩窗口，但不能消灭阅读。

Fail → Understand → Retry

失败必须能回答“我为什么失败”和“下次改什么”。检查点要让玩家快速回到学习点。

12
Trade-offs

每一个“更难”都要支付代价。

改动可能获得可能失去该问的问题
追兵更快紧张感观察与探索玩家是因为追逐改变路线，还是只来不及看？
平台更窄精度要求触屏稳定性失败来自判断错误，还是输入误差？
时限更短节奏、紧迫试验路线的自由倒计时是否真的影响决策？
必收水晶更多路线规划重复劳动水晶位置是否产生选择？
新增动作技巧表达认知负担玩家是否已经在安全区学会它？

产品设计的工作不是避免代价，而是知道自己在换什么。

13
Requirement Writing

把一句模糊需求，改写成可执行方案。

不够：“太简单了，做难一点。”
进步：“骷髅太慢，让它快一点。”
可执行：“第 60–100 距离这一段，我几乎感觉不到骷髅压力，所以一直直跑，不需要看危险条。先只把追兵基础速度 5.6 → 6.1，其他不动。我希望这里至少出现一次明显追近，但正常操作仍能逃掉。各跑 3 次，如果玩家因为追兵而改变动作，而不是因为跳跃突然变难，再考虑保留。”
14
The 7-Part Design Sentence

以后每个修改，至少说清楚这 7 项。

1 位置在哪一段？
2 现象现在玩家怎么做？
3 原因你认为为什么？
4 改动具体改什么？
5 目标想让玩家怎么变？
6 代价可能伤害什么？
7 证据怎么测试？
填写模板：
在 ______ ，玩家现在会 ______ 。我认为原因是 ______ 。我想先只把 ______ 从 ______ 改成 ______ 。我希望玩家因此开始 ______ 。代价可能是 ______ 。我会测试 ______ 次；如果 ______ ，就保留，否则回退。
15
Product Detail Checklist

完整游戏产品，需要描述的不止“玩法”。

目标

赢什么？一局多久？为什么继续玩？

核心循环

观察 → 行动 → 反馈 → 奖励/失败 → 再决策。

动作词汇

移动、跳、冲刺、滑、攀爬，各自什么时候有意义？

关卡语法

平台、障碍、分叉、节奏、检查点如何组合？

镜头与可读性

玩家是否能提前看见落点与危险？

难度曲线

教什么？何时测试？何时组合？何时放松？

失败与恢复

为什么失败？多久重回练习点？

奖励与风险

为什么走危险路线？为什么收集？

节奏

紧张、缓冲、高潮如何交替？

输入设备

键盘和触屏是否考同一种技能？

参数

速度、距离、宽度、时间要写成数字，而不是形容词。

验证

主观评价 + 可观察行为 + 失败原因。

16
Next Lesson Challenge

下节课不是“把游戏做难”。
是做一次真正的设计实验。

任务 A：A/B 两版

  1. 标准版两局
  2. 硬调版两局
  3. 指出至少 3 个具体差异
  4. 区分“紧张”“技巧”“烦躁”

任务 B：写三个方案

  1. 每个只选 1 个主要难度轴
  2. 写位置与原因
  3. 写具体参数/规则
  4. 写代价与测试方法

任务 C：只实现一个

先做最小变化，不允许同时把所有旋钮都拧紧。

任务 D：三次测试

跑三次，记录失败原因和动作是否改变。然后决定：保留、回退、还是提出下一假设。

17
Assessment

本课真正的“通关条件”

从 “难一点”→ “我知道哪里有问题，我有一个方案，我知道它的代价，我知道怎么验证。”

维度1 体感2 定位3 设计4 产品思维 表达“太简单”指出具体段落说明原因与改法方案 + 取舍 + 验证 修改要求“更难”选一个参数选一个难度轴最小实验并回退/保留 测试“好/不好”说哪里失败说为什么失败用多次测试支持判断
教师验收：不要求学生使用术语。只要他能独立给出“具体位置 + 原因 + 解决办法 + 验证”，就算真正跨过这一步。
