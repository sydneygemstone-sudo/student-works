# Michael 下一课：从“难一点”到可执行的游戏设计

日期：2026-09-21
项目：Crystal Escape / 水晶逃生
用途：教师备课与学生下节课的产品设计训练

## 1. 家庭测试后的教学信号

家庭测试反馈被归纳为：“现在感觉太简单，希望做得难一点。”

这是一条有效的体感反馈，但还不是可执行的产品需求。它缺少至少五个信息：

1. 哪一段太简单：起点、连续平台、追逐、收集、出口，还是整局节奏？
2. 为什么简单：反应时间太长、跳跃距离太短、路线没有选择、追兵没有压力、失败成本太低，还是目标太少？
3. 想增加哪一种难度：时间压力、操作精度、路线判断、资源取舍、记忆、风险选择、追逐压力等？
4. 希望玩家因此做出什么新的决定或技巧？
5. 怎么验证改动有效，而不是只让玩家更烦？

公开记录只描述“反馈的具体程度”，不对学生的语言能力或人格作标签。私人聊天截图不进入公开仓库。

## 2. 本课的核心命题

**体感可以启动讨论，但不能直接驱动实现。**

“太简单”描述的是玩家感受。
“难一点”描述的是方向。
真正可执行的需求必须继续回答：

> 在哪里？什么机制？为什么？改什么？希望玩家怎么改变行为？改完怎么测？

本课的目标不是训练孩子说得更长，而是训练他说得更**精确、可执行、可验证**。

## 3. 刻意制作的反例：vague-hard 参数硬调版

为了忠实执行“难一点”这句话，同时让学生看到模糊需求的后果，新增一个不追求最佳趣味性的对照版本：

| 参数 | 标准版 1.1 | vague-hard 1.2 实验版 | 难度轴 |
|---|---:|---:|---|
| 必收水晶 | 8 / 12 | 10 / 12 | 目标负担 |
| 时限 | 300 秒 | 180 秒 | 时间压力 |
| 玩家速度 | 8.8 | 8.35 | 操作余量 |
| 重力 | 24 | 26.5 | 跳跃精度 |
| 跳跃力度 | 10.8 | 10.35 | 跳跃精度 |
| Coyote time | 0.16 秒 | 0.08 秒 | 输入容错 |
| Jump buffer | 0.20 秒 | 0.10 秒 | 输入容错 |
| 追兵基础速度 | 5.6 | 6.35 | 追逐压力 |
| 追兵最高速度 | 8.5 | 9.35 | 追逐压力 |
| 追赶修正系数 | 0.55 | 0.68 | 追逐压力 |

这个版本故意一次改变很多变量。它大概率会“更难”，但即使学生更不喜欢，也很难回答究竟是哪一个改动导致问题。这正是实验要证明的事情：

**模糊输入会制造不可诊断的输出。**

## 4. 下节课的学习目标

下节课结束时，Michael 应能完成以下五件事：

1. **定位**：指出具体区段或具体机制，而不是只说整局“太简单/太难”。
2. **归因**：说明造成体感的原因，例如“第 7–9 平台落点太宽，所以不用观察就能一直向前跑”。
3. **选轴**：从多个难度轴中只选 1–2 个进行实验，而不是所有参数一起加压。
4. **提出方案**：把问题改写为至少一个可实现的设计方案，并说明方案的代价。
5. **定义证据**：说清楚什么测试结果会让自己认为这次改动成功。

## 5. 难度的九个常用旋钮

| 难度轴 | 可以怎么改 | 主要风险 |
|---|---|---|
| 时间压力 | 更短倒计时、更快移动障碍、更短预告 | 玩家来不及理解 |
| 操作精度 | 更窄平台、更远跳距、更小落点 | 触屏容易变成挫败 |
| 追逐压力 | 追兵更快、恢复更快、距离更近 | 玩家没有观察空间 |
| 路线判断 | 分叉、捷径、安全路/危险路 | 路线提示不清会变成猜 |
| 动作组合 | 跳+转向、连续跳、冲刺+落点 | 新动作一次出现太多 |
| 信息压力 | 隐藏部分信息、延迟显示 | 容易从挑战变成不公平 |
| 资源取舍 | 水晶、护盾、一次性救命道具 | 资源价值不清就没有选择 |
| 风险/奖励 | 危险路线给更多收益 | 奖励太小则没有真正取舍 |
| 失败成本 | 检查点、重来距离、丢失资源 | 成本过高会浪费练习时间 |

## 6. “更难”与“更好玩”不是同一个变量

### 常见的 Hard but Boring

- 所有东西一起加速。
- 把平台缩得很小，但不给更好的镜头或落点提示。
- 降低输入容错，让同一个动作只是更容易误操作。
- 失败后重复很长一段已经掌握的内容。
- 随机制造无法提前读取的障碍。
- 只增加收集数量，却没有新的路线选择。
- 追兵过快，导致玩家没有时间观察关卡。

### 更值得测试的 Hard and Interesting

- 给玩家一个**新问题**，而不是只缩小误差范围。
- 先让玩家看懂，再逐渐压缩反应时间。
- 一次只增强一个主要变量，方便知道改动有没有价值。
- 让失误可以恢复，保留“差一点”的学习反馈。
- 设置安全路线与高收益危险路线，让玩家主动选择风险。
- 用“教学 → 测试 → 变化”组织同一种机制。
- 失败后快速回到需要练习的地方。

## 7. 经典跑酷案例应该学什么

### Temple Run

官方描述的核心动作非常少：转向、跳跃、滑行；同时收集金币、获得强化并持续跑得更远。重点不是“按钮多”，而是同一组动作被越来越紧凑地组合。

可迁移到 Crystal Escape：
- 保持移动+跳跃这套简单动作；
- 通过障碍排列与预告改变“什么时候跳、往哪边跳”；
- 奖励可以引导玩家主动走更危险的路线。

来源：Imangi Studios, Temple Run
https://imangistudios.com/thegames/temple-run/

### Subway Surfers

App Store 的编辑介绍把其核心概括为简单滑动控制下的 jump / slide / dodge，并强调响应明确、换道和跳跃不应靠猜。

可迁移到 Crystal Escape：
- 操作词汇少并不代表游戏浅；
- 难度可以来自“识别障碍 → 选择正确动作 → 在正确时间执行”；
- 可读性越好，越有资格提高速度。

来源：Apple App Store, Game essentials: Subway Surfers
https://apps.apple.com/au/story/id1453245869

### Roblox Classic Obby / Platformer

Roblox Creator Hub 明确示范：
- Obby 可以从容易开始，逐渐加入移动、推动、伤害等变化；
- 平台的位置、尺寸、朝向都会改变跳跃问题；
- 官方特别提醒：开局跳距过难，玩家可能直接离开；
- Platformer 模板还包含双跳、冲刺、翻滚、长跳、移动平台、单向平台和金币等机制。

可迁移到 Crystal Escape：
- 不要把所有平台一起缩小；
- 先挑一个区段做“平台距离/宽度/方向”的实验；
- 新动作必须先单独教，再与已有动作组合；
- 每次改完必须亲自 playtest。

来源：
- https://create.roblox.com/docs/tutorials/curriculums/building/get-started
- https://create.roblox.com/docs/tutorials/curriculums/building/work-with-parts
- https://create.roblox.com/docs/resources/roblox-connect
- https://create.roblox.com/docs/input/mouse-and-keyboard

### Vector

Steam 官方页面把核心动作描述为 run / vault / slide / climb，并把后段挑战描述为快速的 timing puzzles。

可迁移到 Crystal Escape：
- 跑酷的“高级感”不一定来自更快；
- 可以来自对动作时机、动作顺序和路线读法的掌握；
- 更丰富的动作词汇只有在前面已经教会玩家时才值得加入。

来源：Steam, Vector
https://store.steampowered.com/app/248970/

## 8. 产品需求表达公式

### 不可执行

> 太简单了，做难一点。

### 比较好

> 骷髅追得太慢，让它快一点。

### 可执行

> 第 60–100 距离这一段，我几乎感觉不到骷髅的压力，所以我一直往前冲，不需要看危险条。先只把追兵基础速度从 5.6 提到 6.1，其他参数不动。我希望玩家在这一段至少有一次看到危险条进入黄色，但正常操作仍可以逃掉。我们各跑 3 次，看是不是因为追兵而改变了动作，而不是因为跳跃突然变难。

推荐模板：

> **位置**：在 ______
> **现在发生**：玩家现在会 ______
> **我认为原因是**：因为 ______
> **我想尝试**：只把 ______ 从 ______ 改成 ______
> **我希望玩家因此**：开始 ______
> **代价可能是**：会让 ______ 变差
> **验证方法**：我会跑 ______ 次；如果 ______，就保留，否则回退。

## 9. 产品设计不是“提要求”，而是“提出可检验的解法”

下一课使用四步循环：

1. **Problem**：具体问题是什么？
2. **Hypothesis**：为什么会发生？
3. **Solution**：最小改动是什么？
4. **Evidence**：怎样知道解决了？

要求每次只改一个主要假设。这样即使方案失败，也能学到东西。

## 10. 下节课课堂流程建议

### A. 10 分钟：A/B 盲测

先玩标准版，再玩 vague-hard 版。禁止先看参数表。

记录：
- 哪一段更紧张？
- 哪一段只是更烦？
- 哪一次失败让你知道“我下次应该怎么做”？
- 哪一次失败你只觉得系统在针对你？

### B. 10 分钟：揭晓参数

打开参数表。让 Michael 找出：
- 哪些参数改变了“技能要求”；
- 哪些只是改变“容错”；
- 哪些改变“节奏”；
- 哪些同时改变导致无法判断因果。

### C. 15 分钟：经典案例拆解

用 lesson-difficulty-design.html 的 Temple Run、Subway Surfers、Roblox、Vector 页面完成“动作词汇 / 难度来源 / 反馈 / 取舍”四格分析。

### D. 20 分钟：写三个具体改动

每个改动必须包含：
- 位置；
- 原因；
- 一个主要难度轴；
- 参数或规则变化；
- 预期玩家行为；
- 代价；
- 测试方法。

### E. 20 分钟：只实现一个

从三个方案中选一个。只改一组相关变量，跑 3 次，再决定保留/回退/继续。

## 11. 课堂验收标准

不以“做出了更难的游戏”为验收。

真正的验收是 Michael 能独立说出一条类似下面的话：

> “我想改第 8 个平台，因为现在它太宽，我完全不用修正方向。我想先把宽度从 6.4 调到 5.4，别的参数不变。我希望玩家需要在起跳前对准一次，但不要让第一次尝试就几乎不可能。我会跑三次；如果我能看懂自己为什么掉下去，而且第二第三次明显进步，就说明这个难度有用。”

这说明他已经从“表达体感”进入了“设计解决方案”。
